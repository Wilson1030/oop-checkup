  [中等] 检查项 4 · static 是否被滥用
        违反标准：全局状态破坏封装
        出处：Java 教科书通识
────────────────────────────────────────────────────────────

  MovieTicket  —  4 个 static 非 final 字段（全局变量）

      MovieTicket.java:3   class MovieTicket
          static String MovieName
          static String theatreName
          static double pricePerTicket
          static int numberOfTickets

    ▸ 发生了什么
      MovieTicket 里有 4 个 static 且非 final 的字段：
          static String MovieName
          static String theatreName
          static double pricePerTicket
          static int numberOfTickets

    ▸ 你在 C 里会怎么写
      这就是 C 的全局变量。
      你在 C 里写  int g_count;
      在 Java 里写  static int count;
      语义上是同一个东西 —— 一块所有代码都能读写的内存。

    ▸ 为什么是问题
      任何一处代码都能改它，出问题时你无法知道是谁在什么时候改
      的。
      调试这类 bug 只能靠通读全部代码。
      如果程序有多线程，它还会直接导致数据竞争。

    ▸ 试试
      问自己一个问题：这个状态属于谁？

          属于某个具体的东西  →  变成那个对象的实例字段
          属于整个程序        →  也应该有一个对象来持有它，
                                  并且只通过方法访问

      把 MovieTicket 的这些字段改成实例字段，然后把 
      MovieTicket 变成一个正常的对象。

    ▸ 但要注意
      常量（static final）不在此列，那是正常且推荐的。
      真正需要全局唯一的资源（连接池、配置），可以用单例，
      但要把访问收敛到方法里，而不是直接暴露字段。
