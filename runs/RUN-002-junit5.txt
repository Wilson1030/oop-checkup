    ▸ 你在 C 里会怎么写
      你在 C 里遇到这种情况会怎么写？
      你多半会定义一个 struct，把这几个字段装进去，然后传它的指
      针。
      因为你知道它们是一个整体 —— 拆开传又累，参数顺序还容易写
      反。

      那你为什么在 Java 里没这么做？
      多半是因为「定义一个类」看起来比「定义一个 struct」重得多
      ，
      而你被教成「类是很严肃的东西，不能随便建」。这个观念是错的
      。

    ▸ 为什么是问题
      参数顺序写反时编译器往往不报错（类型相同），要到运行时才炸
      。
      以后要给这组数据加一个字段，你得同时改 28 处方法签名，漏一
      处就编译不过。

    ▸ 试试
      把它们收进一个类：

          class /* 你来起个名字 */ {
              Deque<Integer> indexes;
              Object messageOrSupplier;
          }

      这 28 个方法的参数列表会全部缩成 1 个。
      起名这一步很重要 —— 如果起不出名字，说明它们可能确实不是
      一个概念。

      再往前一步，这才是「面向对象」的部分：
      既然这个新类掌握了 indexes、messageOrSupplier 的全部信息，
      那么 assertArrayEquals() 这样的方法
      本来就该长在它身上，而不是留在外面。
      C 的 struct 和 Java 的对象，唯一的区别就是：对象能带上操作
      自己的函数。

    ▸ 但要注意
      如果这几个参数在业务上确实无关、只是碰巧同类型同名，那就不
      必封装。
      判断标准只有一条：它们是不是同一件事的组成部分。
