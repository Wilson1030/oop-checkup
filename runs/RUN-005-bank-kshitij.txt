  [待确认] 检查项 2 · 是否避免散装参数传递
        关联标准：Data Clump / Long Parameter List
        出处：Fowler《重构》坏味道 #3 #4
────────────────────────────────────────────────────────────

  (Connection connection, Scanner scanner)  跨 3 个类、3 个方
  法，共出现 3 次

      AccountManager.java:8   AccountManager(Connection connection, Scanner scanner)
      Accounts.java:9   Accounts(Connection connection, Scanner scanner)
      User.java:13   User(Connection connection, Scanner scanner)

    ▸ 发生了什么
      (Connection connection, Scanner scanner) 这 2 个参数，在
      AccountManager、Accounts、User 共 3 个类的 3 个方法里重
      复出现。

    ▸ 你在 C 里会怎么写
      你在 C 里遇到这种情况会怎么写？
      如果这几个东西是一个整体，你多半会定义一个 struct，然后
      传指针 ——
      因为拆开传又累，参数顺序还容易写反。

      那你为什么在 Java 里没这么做？
      多半是因为「定义一个类」看起来比「定义一个 struct」重得
      多，
      而你被教成「类是很严肃的东西，不能随便建」。这个观念是错
      的。

    ▸ 为什么是问题
      如果它们确实是一个整体：参数顺序写反时编译器往往不报错（
      类型相同），
      要到运行时才炸；以后加一个字段，你得同时改 3 处方法签
      名。

    ▸ 怎么判断
      这一条需要你自己判断 —— 请回答一个问题：

          你能给 connection、scanner 起一个名字吗？

          起得出来  →  它们就该是一个类：

              class /* 你起的那个名字 */ {
                  Connection connection;
                  Scanner scanner;
              }

          起不出来  →  忽略本条，它们只是碰巧同名。

      如果起出来了，再往前一步 —— 这才是「面向对象」的部分：
      既然这个新类掌握了全部信息，那么操作这些数据的方法
      本来就该长在它身上，而不是留在那 3 个地方。
      C 的 struct 和 Java 的对象，唯一的区别就是：对象能带上操
      作自己的函数。

    ▸ 但要注意
      本条为「待确认」而非「违反」，因为「这几个参数是不是同一
      个概念」
      无法由代码结构判断，只能由写代码的人判断。
      而做这个判断的过程，恰恰就是面向对象设计本身。

  [中等] 检查项 6 · 入口方法是否过度承担
        违反标准：Long Method（main 特化）
        出处：Fowler《重构》坏味道 #6
────────────────────────────────────────────────────────────

  BankingApp.main()  —  93 行

      BankingApp.java:13   BankingApp.main()

    ▸ 发生了什么
      BankingApp.main() 有 93 行。

    ▸ 你在 C 里会怎么写
      这就是一个 C 程序的形状：一个 main，从头执行到尾。
      在 C 里这很自然 —— 程序就是一条指令流。
      你把这条指令流原样搬进了 Java 的 main 里。

    ▸ 为什么是问题
      93 行的方法没法单独测试、没法复用、也很难读懂。
      但更重要的是：它说明这个程序里还没有「对象」这个概念 —
      —
      所有东西都排在同一条时间线上，没有任何东西是「有身份
      的」。

    ▸ 试试
      在 main 里找一段连续的逻辑，问自己：

          「这一段在处理什么东西？」

      那个「东西」就应该是一个类。
      把这段逻辑，连同它反复操作的那几个变量，一起搬进那个类。

      重复几次之后，main 会缩短成几行 —— 只剩下创建对象、把
      它们接起来。
      那才是 main 该做的事。

    ▸ 但要注意
      如果这确实是一个一次性的脚本式小程序，main 长一点可以接
      受。
      但超过 100 行时，里面通常已经藏着好几个不同的概念了。
