## 五、检查项 3 的失败机理

五条误报可归为三类，全部是**库代码特有的约束**：

| 类型 | 案例 | 为什么无法用多态 |
|---|---|---|
| 对**外部类型**做分派 | `instanceof CharSequence / Collection / Map` | 你无法给 `String`、`Collection` 添加方法 |
| 对**语言原生类型**做分派 | `instanceof boolean[] / byte[] / char[]` | Java 的原生数组之间没有共同超类型 |
| **状态机**而非类型分派 | `switch (state)` | 状态不是类型，多态不适用 |

学生的应用代码几乎不会遇到前两类——他们分派的是**自己定义的类**
（如 `instanceof ElevatorRequest`），而那正是多态适用的场景。
