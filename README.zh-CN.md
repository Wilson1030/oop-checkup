# oo-checkup

**给从 C 转向 Java 的学习者做的「面向对象转换检查表」。**

[English](README.md)

你的代码能编译、能跑、作业能满分。所以**没有任何东西会告诉你「你写的还不是面向对象」**——
编译器不管，测试通过，老师只看输出对不对。

这个工具就是来填这个反馈真空的。它不改你的代码，只告诉你哪里还在用 C 的思维写 Java，以及为什么那是个问题。

## 快速开始

需要 JDK 17+（构建才需要 Maven）。

```bash
git clone https://github.com/<your-name>/oo-checkup.git
cd oo-checkup
mvn package
```

```powershell
.\checkup.bat examples\before          # Windows
```
```bash
./checkup.sh examples/before           # macOS / Linux
```

启动脚本已经把终端编码处理好了。

| 参数 | |
|---|---|
| `--lang zh\|en` | 报告语言（默认 `zh`） |
| `--detail N` | 每个检查项最多展开 N 处（默认 3） |
| `--include-tests` | 包含测试目录 |
| `--summary` | 只输出一行摘要 |
| `--batch` | 把路径下每个子目录各当一个项目 |

<details>
<summary>不想用脚本，直接调 java</summary>

```bash
java -jar target/oo-checkup.jar <路径> > 报告.txt
```

**导出到文件最省事**——写文件时编码不受终端影响，不会乱码。

⚠️ **PowerShell** 里 `-Dfile.encoding=UTF-8` 必须加引号，否则会从 `.` 处被拆成两个参数，
报 `找不到或无法加载主类 .encoding=UTF-8`：

```powershell
java "-Dfile.encoding=UTF-8" -jar target\oo-checkup.jar <路径>
```

## 检查表

每一项都对应一条公认标准，**并注明出处**。你可以质疑工具，但可以去查原文。

| # | 检查项 | 标准 | 出处 | |
|---|---|---|---|---|
| 1 | 数据与行为是否结合 | Anemic Domain Model | Fowler, 2003 | ✅ |
| 2 | 是否避免散装参数传递 | Data Clump / Long Parameter List | 《重构》#3 #4 | ⚠️ 待确认 |
| 3 | 是否用多态替代类型判断 | Switch Statements | 《重构》#11 | ✅ |
| 4 | `static` 是否被滥用 | 全局状态破坏封装 | Java 教科书通识 | ✅ |
| 5 | 封装是否完整 | public 可变字段暴露内部表示 | 《重构》#5 关联 | ✅ |
| 6 | 入口方法是否过度承担 | Long Method（main 特化） | 《重构》#6 | ✅ |
| 7 | 是否避免基本类型偏执 | Primitive Obsession | 《重构》#2 | ⬜ 未实现 |

## 一条发现长什么样

```
────────────────────────────────────────────────────────────
  [严重] 检查项 1 · 数据与行为是否结合
        违反标准：Anemic Domain Model
        出处：Martin Fowler, AnemicDomainModel, 2003
────────────────────────────────────────────────────────────

  Book  —  5 个字段，6 个 getter/setter，0 个业务方法

      Book.java:7   class Book
          LibraryService  访问它 16 次
          Main            访问它 4 次
          SearchService   访问它 3 次

    > 你在 C 里会怎么写
      这正是 C 的写法：一个 struct 存数据，一组函数在外面操作它。
      你把 struct 改名叫 class，把那些函数搬进了另一个类，
      但结构一点没变 —— 数据在一边，操作数据的代码在另一边。

      在 C 里你别无选择，语言就只给了 struct。
      在 Java 里你有选择，只是没用上。

    > 试试
      找一个只用到 Book 自己字段的方法，把它搬进 Book。
      搬完你会发现：它不再需要参数了 —— 因为数据就在手边。

      这就是「对象」这个词的全部含义：数据，加上操作这些数据的函数，
      被放在同一个地方。不是继承，不是多态，就是这个。

    > 但要注意
      不是所有逻辑都该搬进来。涉及多个对象协作、或依赖外部资源的逻辑，
      留在 Service 里是对的。
```

每条发现有五段：

| | |
|---|---|
| **发生了什么** | 客观事实 + 行号，先确认它没说错再信 |
| **你在 C 里会怎么写** | ← 关键。你不是不懂封装的定义，是不知道自己写的 Java 还是 C |
| **为什么是问题** | 具体后果，不讲大道理 |
| **试试** | 一个可以立刻执行的动作 |
| **但要注意** | ← 防止改过头 |

## 「待确认」是什么

有些判断**本质上需要理解语义**，静态分析做不准。这类不断言，只提问：

```
  [待确认] 检查项 2 · 是否避免散装参数传递

  (String title, String author)  跨 2 个类、2 个方法

    > 怎么判断
      你能给 title、author 起一个名字吗？

          起得出来  →  它们就该是一个类
          起不出来  →  忽略本条
```

这不是逃避。**起名这个动作本身，就是在判断「这几个东西是不是同一个概念」**——
而那正是面向对象设计。

## 设计原则

**1 · 给检查表，不打分。**
打分隐含「存在一把普适的尺子」。而那把尺子只在「这个项目该怎么设计」这一层才需要，
恰恰是没有标准的一层。500 行的库存系统和 500 行的游戏，合理结构本来就不同。

```
✗  你得 34 分                      需要普适标准，站不住
✓  (ip, port) 跨 3 个类            客观事实，不需要标准
   被 7 个方法传递
```

**2 · 检测必须确定性。**
误报一次，读者就再也不信你了。所以：

- *是什么 / 在哪 / 违反哪条标准* → 规则引擎，纯静态分析，可复现
- *为什么 / 怎么改* → 解释层，可选由 LLM 增强

**LLM 永远不参与判定**，否则它会幻觉出不存在的问题。同一份代码跑两次，检出逐字节相同。

**3 · 绝不自动改代码。**
一旦工具替你改了，你就不动脑了，全部价值归零。

## 这个工具是怎么被验证的

不是「跑通了就发」。完整记录在 [`runs/`](runs) 和 `PREREGISTRATION-v*.md`。

| 轮次 | | 抓到了什么 |
|---|---|---|
| 001 | ❌ | 把 Guava 的 69 个手写重载判成了坏味道 |
| 002 | ❌ | **拦下一次事后调参**：某阈值卡在 64% 和 57% 之间，能让数字瞬间好看——拒绝采用 |
| 003 | ❌ | 工具类不能按名字认（`Strings` 不叫 `StringUtils`） |
| 004 | ⚠️ | 80.6% 算「通过」，但对照组单独看只有 14%——被样本比例掩盖的失败 |
| 005 | ❌ | **盲测暴露样本偏差**：前四轮的学生样本里，一个控制台菜单程序都没有，而那是最典型的形态 |
| 006 | ✅ | **97.8%**（44/45），盲测组 100% |

三个机制，各自抓到了别的机制抓不到的东西：

- **对照组**（Guava / JUnit5）——只跑学生代码的话，第一轮那 13 条检出看起来完全合理
- **预注册**（每次改动前写死预测）——拦下了我自己的事后调参
- **盲测**（下载后不看代码直接跑）——暴露了样本集偏差

任何一个缺席，缺陷都会活到真实用户手上。

## 已知局限

- 检查项 2、7 是**语义类**判据，只输出「待确认」
- 检查项 1 的外部访问次数是**按成员名匹配的近似值**（未接入类型解析）
- 检查项 2 要求参数团**跨 ≥2 个类**。「一个 `XxxManager` 包打天下」的写法会漏报——
  已实测确认的缺口，暂未修改
- 已知残留误报 1 条（Guava `Suppliers` 内部优化路径）
- 验证样本 13 个（2 个成熟开源库 + 11 个真实学生仓库），规模仍小
- **只支持 Java**

## 项目结构

```
src/main/java/com/ooc/
├── ir/          统一中间表示 —— 换解析器不用动这里
├── parse/       JavaParser → IR（唯一耦合解析器的地方）
├── rules/       六条规则，一条一个文件
├── explain/     Explainer 接口 + TemplateExplainer
└── report/      检查表渲染

checkup.bat / .sh   启动脚本（已处理编码）
examples/           before / after 演示代码（可编译运行）
testdata/           规则的单元测试用例
runs/               六轮验证的原始输出与逐条核验
PREREGISTRATION-v*.md   每轮改动前写死的判据与预测
```
